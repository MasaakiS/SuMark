# SuMarkのファイル保存・オープン時のデータと表示の関係まとめ

## 1. ファイルオープン（openFile, openFileFromPath）
- ファイル選択ダイアログでMarkdownファイルを選択。
- readTextFileで内容を読み込み。
- 画像パスやCSVリンクをresolveRelativeImages/resolveRelativeCsvLinksで変換。
- Notion形式の複数行テーブルセルはpreprocessNotionMarkdownで正規化。
- Markdown→HTML変換（marked.parse）。
- タブ（tabs[]）に{filePath, title, content, isModified, ...}として格納。
- エディタ表示はHTML（editor.innerHTML）で再現。

## 2. ファイル保存（saveFile, saveAsFile）
- getMarkdown()でeditor.innerHTML→Markdownへ変換（Turndown利用）。
- resolveImagesForSaveで画像のasset://URLを相対パスに戻し、Base64画像はファイル保存＋パス差し替え。
- writeTextFileでMarkdownとして保存。
- タブ情報（tabs[]）のfilePath, title, isModifiedを更新。

## 3. 表示とデータの同期
- ファイルオープン時はMarkdown→HTML変換して表示。
- 保存時はHTML→Markdown変換してファイル出力。
- タブごとに内容・パス・変更フラグを管理。
- 画像やCSVなどの相対パスは、表示時と保存時で変換ロジックが異なる（asset://, data: → 相対パスなど）。

## 4. バグが起きやすいポイント
- Markdown→HTML, HTML→Markdownの相互変換で情報が失われる場合。
- 画像や埋め込みリソースのパス変換ミス。
- タブのisModified管理ミスで保存漏れ。
- Notion特殊形式やGFM拡張の正規化不足。

## 5. 参考関数
- openFile, openFileFromPath, saveFile, saveAsFile, getMarkdown, setMarkdown, resolveRelativeImages, resolveImagesForSave, preprocessNotionMarkdown など。
